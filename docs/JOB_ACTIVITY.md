# 업무 목록의 집계·검토 현황

업무 요청·저장 이력에서 각 업무의 정량 집계·검토 상태를 확인합니다. 업무 접수 상태는 계속 **접수됨 · 자동 실행 미연결**입니다. 파일 집계·검토 현황은 실제 DB 기록이며 오피스 캐릭터 시연과 별개입니다.

- **진행 중 전체**: 해당 업무의 모든 실행 중 대기/실행 건수입니다. 첨부의 최근 실행이 취소되어도 그보다 먼저 접수한 실행이 처리 중이라면 포함합니다.
- **첨부별 최근 집계**: 파일마다 가장 최근에 접수한 실행 하나를 기준으로 완료·실패·취소를 셉니다. 접수 시각이 같으면 실행 ID 내림차순입니다. 성공한 결과만 골라 표시하지 않습니다.
- **검토 대기**: 최근 실행이 완료되고 파일 메타데이터 3종이 있으며 아직 결정이 없는 경우입니다.
- **승인 기록 / 반려 기록**: 해당 최근 실행에 저장된 당시 결정입니다. 파일 무결성·현재 결정 유효성을 확인했다는 표시가 아닙니다.
- **요약만 보관**: 최근 완료 실행에 파일 메타데이터 3종이 없는 이전 결과입니다. 집계 이력이 없으면 별도로 표시합니다.

이전 실행이 승인됐어도 새 실행을 접수하면 새 실행을 기준으로 표시합니다. 파일이 여러 개라면 파일마다 다른 실행·검토 상태가 함께 나타날 수 있습니다. 진행 중 전체 건수와 첨부별 최근 실행 건수는 기준이 달라 합계가 같지 않을 수 있습니다.

## 상태 갱신과 결과 이동

**집계·검토 상태 새로고침**은 목록 첫 페이지와 선택한 업무의 현황을 갱신하면서 열어 둔 결과·검토 의견·열 선택을 유지합니다. 조회 연결이 실패해도 기존 현황·입력을 남기며 오류를 표시합니다. 상태 버튼이나 오류의 다시 연결로 재시도합니다. 목록의 더 보기 페이지는 다시 첫 페이지부터 표시하지만 이미 선택한 이전 페이지 업무의 상세는 유지합니다. 기존 **이력 새로고침**은 업무 상세 전체를 다시 불러오는 기능입니다.

현재 화면에서 집계 접수·취소, 진행 중 작업의 상태 전환, 검토 결정 성공/충돌을 확인하면 현황을 갱신합니다. 다른 화면/서버에서 일어난 변경을 실시간으로 구독하지 않습니다. 해당 경우 상태 새로고침을 사용하세요. 페이지가 오래 열려 있으면 마지막 조회의 기록이 보일 수 있습니다.

업무 목록의 **최근 집계·검토 보기**는 그 업무의 첨부별 최근 실행들 중 가장 최근 접수한 실행으로 이동합니다. 선택 업무의 **집계·검토 현황**에는 파일별로 바로 가기가 있습니다. URL의 `job`, `file`, `run`을 함께 저장해 같은 계정에서 새로고침/재로그인 후 해당 이력을 복원합니다. 선택한 실행이 과거 기록이어도 목록 현황은 첨부별 가장 최근 실행을 표시합니다.

완료 실행은 저장 요약·다운로드·검토 화면을 바로 엽니다. 이 링크는 원본 미리보기나 재집계가 필요하지 않아 입력 원본이 분실된 경우에도 보관 결과를 조회할 수 있습니다. 미완료 실행은 작업 목록에서 상태·취소를 확인하고 완료 후 결과 보기 버튼을 사용합니다. 새 집계를 접수하려면 파일 미리보기에서 현재 설정을 확인·저장하세요. 잘못된 업무/파일/실행 연결이나 다른 계정의 URL은 기존 소유권 검사로 차단합니다.

## API·구조

DB 스키마 v8을 유지합니다. `GET /api/jobs`의 각 job과 `GET /api/jobs/:id`의 job에 `activity`를 추가합니다. 업무 생성 응답은 현황을 포함하지 않을 수 있습니다.

```json
{
  "activity": {
    "active": { "queued": 0, "running": 1 },
    "latest": [
      { "runId": "실행 UUID", "fileId": "첨부 UUID", "filename": "합성.csv", "revision": 1, "status": "completed", "review": "pending" }
    ]
  }
}
```

latest는 파일당 하나이며 접수 시각·실행 ID 내림차순입니다. review는 완료일 때 pending/approved/rejected/summary_only, 그 외에는 null입니다. 계정과 현재 조회 페이지의 업무 ID로 범위를 제한한 일괄 SQL 조회를 사용합니다. 결과 본문·검토 의견·원본 해시·비공개 경로를 이 현황에 넣지 않으며 입력·출력 파일을 읽거나 생성하지 않습니다. 따라서 목록의 승인 기록은 파일 변조/분실 여부를 반영하지 않습니다. 결과 상세의 [검토 무결성 검사](RESULT_REVIEW.md)를 사용하세요.

세션·계정 전환·소유권·페이지 제한·no-store·nosniff는 기존 업무 API와 같습니다. 상태 필터·검색·목록 자동 구독·오피스 캐릭터 연동은 별도 후속 작업입니다.
