# 파일 미리보기와 분석할 열 선택

로그인 → 저장된 업무 상세 → 첨부 파일의 **미리보기** → 시트·제목 행 확인 → 분석할 열 체크 → **열 선택 저장** 순서로 사용합니다. 새로고침 후 같은 파일의 미리보기를 열면 저장한 시트·제목 행·열이 복원됩니다. 계정이 같으면 다른 브라우저에서도 복원됩니다.

이번 기능은 분석 준비 단계입니다. 미리보기·열 선택 저장만으로 집계·AI 호출·결과물 생성·원본 수정은 하지 않습니다. 저장 후 별도의 기초 집계 실행을 지원합니다. 오피스 캐릭터 시연과도 연결하지 않습니다.

## 표시와 지원 범위

- CSV: UTF-8 BOM 허용. 첫 논리 행의 인용부호 바깥에서 쉼표·세미콜론·탭을 추정합니다. 인용 필드의 구분자·줄바꿈·겹따옴표를 처리합니다. 구분자를 추정할 수 없는 복잡한 파일은 쉼표 CSV로 다시 저장하세요.
- XLSX: 첨부 단계에서 허용한 일반 OOXML 통합 문서. 시트 선택, 공유·인라인·리치 텍스트, 희소 셀·행을 지원합니다. 제목 행은 첫 1~20행 중 선택합니다.
- 열은 `A · 만족도`, `B · 만족도`, `C · 제목 없음`처럼 위치와 제목을 함께 표시합니다. 중복·빈 제목도 열 번호로 식별하며 저장 값은 0부터 시작하는 원본 열 위치입니다.
- 제목 다음 **최대 20행**, 셀 **200자**, 열 제목 **120자**를 표시합니다. 줄임은 표시 범위에만 적용하며 원본은 보존됩니다.
- 미리보기 전체 파싱 한도: **마지막 행 번호 20,000 / 100열 / 100,000셀**. XLSX는 실제 셀 수와 행별 마지막 열 위치까지의 누적 칸 수도 제한합니다. 공유 문자열은 최대 100,000개입니다. 초과하면 일부만 분석 가능한 것처럼 표시하지 않고 422 오류를 반환합니다. 업로드·원본 다운로드 한도와는 별개이므로 보관 가능한 파일도 미리보기가 제한될 수 있습니다.
- 행 번호는 원본 기준입니다. ‘제목 이후 행 수’는 빈 행을 포함한 물리적 범위이며 실제 응답자 수·유효 응답 수가 아닙니다. XLSX 메타데이터의 dimension만으로 행 수를 부풀리지 않으며 기록된 마지막 행을 기준으로 합니다.
- XLSX 수식은 `[수식: 계산하지 않음]`으로 표시하고 캐시된 결과도 계산값으로 사용하지 않습니다. 숫자·날짜는 원본 저장값을 표시하므로 날짜 일련번호가 보일 수 있습니다. 서식·병합·조건부 서식·차트는 재현하지 않습니다. 숨김 시트·행·열도 표시될 수 있습니다.
- 파일의 HTML·URL·CSV 수식은 텍스트로만 표시합니다. 매크로·외부 연결·수식·스크립트를 실행하지 않습니다. 이 미리보기는 Excel과 같은 렌더러나 파일 내용의 의미 검증을 제공하지 않습니다.

## 저장과 충돌 처리

첨부 파일마다 시트 하나·제목 행 하나·열 1~100개를 저장합니다. 시트·제목 행을 바꾸면 해당 화면의 저장하지 않은 열 선택은 초기화됩니다. 미리보기를 닫을 때도 저장하지 않은 선택은 유지하지 않습니다. 화면에서 저장되지 않은 변경을 안내합니다.

SQLite v4는 기존 계정·업무·첨부를 보존하고 `column_selections` 테이블을 추가합니다. 원본 파일 ID, 시트, 제목 행, 선택 열, 원본 SHA-256, 저장 버전과 시각을 보관합니다. 시트·열·제목 행은 서버에서 실제 원본을 다시 읽어 검증합니다. 클라이언트가 원본 해시나 파일 경로를 지정할 수 없습니다.

다른 화면에서 먼저 저장했다면 오래된 버전으로 덮어쓰지 않고 409를 반환합니다. **저장 상태 다시 불러오기**로 최신 설정을 확인한 후 다시 선택하세요. 연결 오류 때 현재 체크 상태는 유지됩니다. 저장 응답만 유실된 경우에도 같은 방식으로 서버 저장 상태를 확인할 수 있습니다.

원본의 크기·해시가 다르거나 파일이 없으면 미리보기와 선택 저장을 거부합니다. GET 응답 전과 PUT 저장 전에 세션을 재확인하며, 모든 요청은 업무 소유 계정만 접근할 수 있습니다. 외부 전송이나 파싱 결과의 로그 출력은 하지 않습니다.

## API

| 경로 | 동작 |
| --- | --- |
| `GET /api/jobs/:id/attachments/:fileId/preview` | `{ preview, selection }`. 저장된 설정이 있으면 기본으로 적용 |
| `GET .../preview?sheetId=0&headerRow=2` | 지정한 시트·제목 행의 미리보기. CSV 시트 ID는 `csv`, XLSX는 통합 문서 순서의 `0`, `1`, … |
| `PUT /api/jobs/:id/attachments/:fileId/selection` | `{ sheetId, headerRow, columns, revision }` 저장 후 `{ selection }` |

PUT은 JSON, `X-Office-Request: 1`, 유효한 세션이 필요합니다. UI는 `X-Office-Account`도 전송합니다. 최초 revision은 0이며 이후 GET의 selection.revision을 전송합니다. 선택 열은 중복 없는 0 기반 정수입니다. 임의 필드는 거부합니다.

400: 잘못된 요청 형식·선택 값 / 401: 비로그인·계정 전환 / 404: 다른 소유자·없는 첨부 / 409: 저장 충돌·원본 무결성 오류 / 422: 없는 시트·제목 행·열, 빈 시트, 미리보기 한도·파싱 오류.

ZIP·XML 업로드 방어는 [첨부 안내](ATTACHMENTS.md), 계정 복구는 [인증 안내](AUTHENTICATION.md)를 참고하세요. 현재 파싱은 제한된 입력에 대해 Node 프로세스에서 실행하며, 공개 운영을 위한 전용 워커·실행 시간 격리·전체 저장량 제한은 후속 과제입니다. 실제 개인정보 파일은 넣지 않습니다.

선택을 저장한 뒤 실행하는 수동 누락·빈도 집계는 [기초 집계 안내](BASIC_SUMMARY.md)를 참고하세요.
