# AI 초안 승인·반려 기록

2026-10-26 기준, 완료된 AI 텍스트 초안에 소유자의 검토 결정을 한 번 기록합니다. 승인/반려는 검토 기록이며 AI 재실행·외부 발송·파일 반영을 일으키지 않습니다. 정량 집계 파일의 검토 기록·도구 실행 승인과 별개입니다. 기본 AI 실행 비활성 설정도 유지합니다.

## 화면과 API

업무 상세의 AI 실행을 선택해 초안을 확인한 뒤 ‘AI 초안 검토’에서 승인/반려, 검토 의견, 내용·출처 확인 체크를 입력합니다. 반려 사유는 필수입니다. 입력을 바꾸면 확인 체크를 해제합니다. 정상 조회가 끝나고 표시 중인 초안과 서버 검토 대상이 같을 때만 확정할 수 있습니다.

| 요청 | 동작 |
| --- | --- |
| GET /api/jobs/:jobId/ai-runs/:runId/review | 현재 검토 가능 여부·대상 해시·과거 결정과 현재 유효성 조회 |
| POST /api/jobs/:jobId/ai-runs/:runId/review | Idempotency-Key와 targetHash/decision/comment로 결정 확정 |

모든 요청은 계정 인증·현재 업무/실행 소유권을 확인합니다. 쓰기는 기존 동일 Origin·JSON·X-Office-Request 정책을 적용합니다. 쿼리·알 수 없는 필드·잘못된 요청 키/해시/결정은 거부합니다. 의견은 trim된 2,000 UTF-16 단위 이하이며 반려는 비어 있을 수 없습니다. 새 결정 201, 같은 결정 재생 200, 결정/대상/요청 키 충돌 또는 미완료·무결성 실패 409입니다. 다른 계정/업무/실행은 404, 미로그인은 401입니다.

결과 API에는 reviewTargetHash를 추가했습니다. 브라우저는 확인한 원문 SHA-256과 이 값을 검토 상태 응답에 대조합니다. 원문을 아직 확인하지 못했거나 조회 실패/대상 변경이 있으면 새 결정을 막습니다. 초안을 보여 주는 것과 승인 기록을 확정하는 것은 별도 동작입니다.

## 검토 대상과 저장

v11은 ai_run_reviews만 추가하며 기존 테이블을 재작성하지 않습니다. 실행당 한 결정, 계정당 유일한 요청 키를 보장하고 UPDATE/DELETE를 거부합니다. 기록은 검토자·결정·의견·시각·대상 해시·manifest를 보관하며 요청 키/manifest는 공개 응답에 포함하지 않습니다. 검토 의견과 DB·백업은 비공개로 관리해야 합니다.

manifest는 버전, 계정/업무/실행 ID, synthetic/codex 출처, 모델·policyId, 입력 snapshot 해시, 결과 해시, thread/turn ID를 포함합니다. 완료 상태·원격 completed·오류 없음·입출력 형식·원문 해시를 확인한 뒤 manifest를 해시합니다. 사용자에게 표시한 초안에 이 값을 묶어 다른 실행/내용을 승인하지 않도록 합니다. 해시는 사실성·제공자 진위나 전문적 판단을 보증하는 서명이 아닙니다.

새 결정은 BEGIN IMMEDIATE 트랜잭션 안에서 소유권·현재 내용·기존 결정·요청 키를 다시 확인하고 저장합니다. 동일 트랜잭션의 기존 계정 이벤트에는 review.decided/fileId=null/state=ai.approved 또는 ai.rejected만 기록합니다. 의견·초안·키는 알림에 넣지 않습니다. 정량 집계의 검토 건수와 캐릭터 상태는 변경하지 않습니다.

## 재확인·무결성·동시 작업

응답 유실/10초 시간 초과 때 동일한 미변경 payload는 같은 키로 사용자가 재확인할 수 있습니다. 조회·WebSocket 재연결은 POST를 재생하지 않습니다. 같은 키의 다른 결정/의견/대상/실행은 충돌입니다. 다른 화면이 먼저 확정하면 그 기록을 조회하며 새 결정을 덮어쓰지 않습니다. 자동 갱신에서 검토 대상과 상태가 같으면 작성 중 의견·확인 체크를 유지합니다.

이미 확정된 요청의 재전송은 현재 결과가 나중에 손상돼도 기존 기록을 반환할 수 있습니다. 이때 valid=false로 표시하고 이벤트나 결정은 추가하지 않습니다. 현재 결과가 검토 manifest와 다르면 과거 결정은 보존하되 현재 초안에 유효하다고 표시하지 않습니다. 본문을 조회할 수 없어도 실행 메타데이터와 당시 검토 기록을 별도로 확인할 수 있습니다.

needsReview=true는 AI 생성물의 검수가 필요하다는 출처 정보로 유지합니다. 현재 결정 여부는 별도 검토 기록으로 표시합니다. 승인 철회·재검토·복수 검토자·조직 결재선·파일 산출물 검증·오피스 AI 연결은 아직 없습니다. 내용이 바뀌었거나 다시 검토해야 하면 별도의 새 실행에 새 결정을 기록해야 합니다.

## 검증

실제 AI 호출 없이 합성 초안으로 권한·입력·대상 변경·동시 동일/다른 요청·이벤트 실패 롤백·재시작 보존·불변 기록·손상 뒤 유효성·응답 유실·UI 입력 유지·다른 화면 결정 복구를 검사합니다. 사용자 DB에는 합성 초안이나 검토를 만들지 않습니다.
