# 기술 설계 및 실제 AI 연동 검토

## 1. 이번 버전의 경계

현재는 React·Phaser 프론트엔드와 Express·SQLite 백엔드를 실행합니다. Phase 3에서 계정 로그인·복구·원본 첨부·미리보기·분석할 열 저장·수동 기초 집계·업무 요청·접수 이벤트·영구 저장을 구현했습니다. 모든 업무는 계정에 귀속되고 요청 식별자도 계정 범위로 적용합니다. 상태는 `received`, 실행 모드는 `not_connected`로 고정됩니다. 상세 계약과 접근 한계는 [백엔드 안내](../backend/README.md)에 정리했습니다.

오피스 캐릭터는 계속 시뮬레이션입니다. React가 상태를 소유하고 `officeReducer`가 예시 배정·단계를 검증합니다. `useOffice`가 약 15초의 예시 이벤트를 발생시키며 Phaser는 상태를 받아 이동·애니메이션만 렌더링합니다. 저장 요청을 시뮬레이션으로 자동 실행하지 않습니다. 실제 AI 호출·AI 생성 결과물·평가 점수·진행 퍼센트를 만들지 않습니다.

타이머는 새 시연·초기화·언마운트 시 정리됩니다. 이전 시연 ID 이벤트, 완료 이후 이벤트, 순서를 건너뛰는 이벤트, 진행 중 중복 시작을 거부합니다. 시연 이력은 직원당 5개, 예시 이벤트는 60개까지만 메모리에 둡니다. 시연은 새로고침 후 초기화되고 DB에 저장한 요청·접수 이벤트는 복원합니다.

직원은 운영팀장, 데이터 분석가, 교육생 관리 담당, 문서 전문가, 콘텐츠 디자이너, 일정·소통 담당입니다. 공지·메일 시연은 초안 작성을 맡는 문서 전문가에게 배정하고, 일정 시연은 일정·소통 담당에게 배정합니다. 운영팀장은 배정·검토를 시각화합니다. 6개의 독립 AI 런타임을 실행하는 구조가 아닙니다.

기본 인증·소유권·복구 방식과 운영 전 제약은 [계정 안내](AUTHENTICATION.md)에 정리했습니다. 기존 익명 기록은 v2 마이그레이션으로 보존하며 자동 계정 연결은 하지 않습니다.

## 3. Phase 3~6 목표 구조 (계정·API·요청 저장 구현)

```text
브라우저 React / Phaser
   │ HTTPS REST (업무·파일·승인·다운로드)
   │ 인증된 WebSocket (실제 상태 이벤트)
   ▼
Node.js / Express 단일 백엔드
   ├─ 업무 서비스 / 검토·승인 / 접근 통제
   ├─ SQLite (단일 인스턴스 초기 버전)
   ├─ 작업별 격리 저장소 / 출력 검증
   ├─ 실행 큐 / Python 파일 워커
   └─ Codex 어댑터 ─ 비공개 App Server 프로세스
```

마이크로서비스는 도입하지 않습니다. Python은 같은 배포 단위의 별도 제한 프로세스로 실행합니다. 파일 연산은 결정적 코드로 처리하고, 내용 요약·초안처럼 필요한 단계에서만 AI를 호출합니다. 사무실 애니메이션을 위한 AI 호출은 하지 않습니다.

### 업무·파일 모델

- `jobs`: UUID, 소유자·조직, 업무 종류, 실행 모드(`simulation` / `real`), 상태, 생성·시작·종료 시각, 오류 코드, 재시도 횟수.
- `job_events`: 단조 증가 시퀀스, 업무 ID, 실제 이벤트 출처, 상태, 요약, 생성 시각. 로그의 개인정보·비밀 값은 제거.
- `files`: UUID, 업무·소유자, 원본 표시명, 내부 경로, 실제 형식, 크기, SHA-256, 원본/결과물 구분. 파일명으로 경로 구성 금지.
- `approvals`: 검토 대상 결과물 해시, 승인자, 결정·시각. 결과물 변경 시 기존 승인 무효화.
- `schedules`: 시간대 포함 시작·종료 시각, 대상, 충돌 판정 근거. 일정 등록·외부 반영은 별도 승인 이후.

업로드 원본은 `storage/input/jobs/<job-id>/`에 불변 보관합니다. 동기 내보내기는 메모리에서 생성해 응답하며, v7 백그라운드 실행의 CSV·HTML·XLSX는 `storage/output/runs/<run-id>/`에 보존합니다. 임시 폴더에서 처리한 뒤 형식·내용 검증을 통과한 산출물만 공개합니다. 원본 수정·자동 덮어쓰기 금지. DB와 파일 생성의 불일치는 상태 전이와 정리 작업으로 복구합니다.

### 입력·출력 지원 계획 (XLSX/CSV 원본 첨부·기초 집계·CSV 출력 구현, 나머지 자동화 계획)

| 형식 | 계획                                        | 주의 / 비지원 범위                                                                    |
| ---- | ------------------------------------------- | ------------------------------------------------------------------------------------- |
| XLSX | openpyxl 읽기·별도 수정본 저장, pandas 집계 | 수식 재계산 엔진 아님. 매크로·외부 링크 실행 금지, 차트·특수 개체 보존 한계 안내      |
| CSV  | pandas, UTF-8·CP949 감지 및 사용자 확인     | 구분자·열 매핑 확인, 내보내기 수식 주입 방어                                          |
| DOCX | python-docx 읽기·보고서 생성                | 특수 도형·레이아웃 완전 보존 보장 안 함                                               |
| PPTX | python-pptx 생성·본문 추출                  | 기존 테마·애니메이션 완전 편집은 비지원, 레이아웃 검수 필요                           |
| PDF  | 별도 검증된 추출기/변환기 선정 후 지원      | 스캔 OCR·암호화 PDF·정확한 페이지 변환은 초기 비지원. python-docx만으로 PDF 변환 불가 |
| ICS  | 시간대 포함 일정 내보내기                   | 실제 캘린더 변경 아님, UID·escaping·줄 접기·중복 등록 검증                            |

현재 업로드는 5MiB/파일·5개/업무, XLSX 압축 해제 20MiB·1,000개 항목으로 제한합니다. 상세 구현·한계는 [첨부 안내](ATTACHMENTS.md)를 참고하세요. 확장자와 MIME만 신뢰하지 않고 파일 시그니처·압축 구조를 확인합니다. 암호화·손상·매크로 파일은 명시적으로 거부하거나 지원 범위를 안내합니다. 다운로드는 소유권 확인 후 5MiB 이내 원본의 해시 확인 후 제공하며 내부 경로를 노출하지 않습니다.

### 교육생 모니터링 원칙

활동 내용·원본 행·시각을 근거로 연결하고, 근거가 부족하면 ‘판단 근거 부족’으로 표시합니다. 채팅 빈도로 학습 태도를 확정하거나 점수를 임의 생성하지 않습니다. 기존 평가표와 제안본을 구분하며 최종 평가는 교육 운영 담당자가 결정합니다. 테스트 데이터는 ‘가상 교육생 A’ 등 합성 식별자만 사용합니다.

## 4. Codex App Server 검토

확인 기준: 2026-10-21, 현재 머신의 `codex-cli 0.163.0` 및 동일 버전 OpenAI 공개 저장소. 공식 개발자 문서 URL은 이 환경에서 HTTP 403으로 접근할 수 없어, 아래 공식 소스·실제 CLI 도움말·프로토콜 생성 도구로 보완 확인했습니다.

- [OpenAI Codex 공개 저장소](https://github.com/openai/codex)
- [0.163.0 App Server 문서](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/app-server/README.md)
- [공식 App Server 가이드](https://developers.openai.com/codex/app-server) (이번 환경에서 본문 미열람)

실제로 수행한 확인:

```sh
codex --version
codex app-server --help
codex app-server generate-ts --help
codex app-server generate-ts --out /tmp/ai-office-codex-protocol
```

프로토콜 타입 생성은 성공했습니다. 생성물은 조사용 `/tmp`에만 두며 앱에 연동하지 않았습니다. CLI 도움말의 App Server 및 타입 생성 기능에는 `[experimental]` 표시가 있습니다. 따라서 지원되는 공식 인터페이스가 존재한다는 사실과, 모든 버전에서 호환성을 보장하는 안정 API라는 주장은 구분해야 합니다. 버전·생성 스키마를 고정하고 업데이트 시 계약 테스트가 필요합니다.

현재 확인한 전송 방식은 `stdio://`(기본), `unix://`/경로, `ws://IP:PORT`, `off`입니다. Phase 5에서는 같은 실행 서버에서 자식 프로세스의 stdio를 이용하는 방식을 우선 검토합니다. CLI에 WebSocket capability-token·signed-bearer-token 관련 옵션이 있지만 브라우저에서 App Server를 직접 공개 접근시키지 않습니다. 외부 연결은 앱 백엔드가 인증·권한 확인 후 필요한 이벤트만 전달합니다.

생성된 프로토콜에서 `initialize` → `initialized`, `thread/start`, `turn/start` 요청과 `turn/started`, `item/started`, `item/completed`, `turn/completed`, 승인 관련 서버 요청을 확인했습니다. 후속 어댑터는 요청 ID와 thread/turn/job ID를 매핑하고 비동기 알림·서버 요청에 각각 응답해야 합니다. 완료 알림 수신만으로 산출물의 유효성을 확정하지 않으며 turn 오류 상태 및 파일 검증을 함께 확인합니다.

| 실제 이벤트 / 의미          | 앱 상태 계획                                  |
| --------------------------- | --------------------------------------------- |
| 실행 큐 수락                | 배정·대기                                     |
| turn 시작 / item 시작       | 분석 / 실제 도구 실행 (실제 item 종류로 구분) |
| 파일 생성·변경 및 검증      | 결과물 생성 / 검토                            |
| 도구 승인 요청              | 정책상 승인 대기 (업무 결과 승인과 별도)      |
| turn 완료, 산출물 검사 통과 | 사용자 검토 대기                              |
| 오류·중단·시간 제한         | 실패·취소, 복구 가능한 경우만 재시도          |

현재 머신의 Codex 실행 권한·GitHub 프록시 인증은 개발 세션용이며, 완성된 앱의 인증으로 이전할 수 없습니다. 이번 작업에서는 계정 로그인·모델 호출·유료 실행·작업 어댑터의 종단 간 연결을 검사하지 않았습니다. 실제 배포 시 유효한 서비스 인증과 이용 조건·비용·데이터 전송 정책을 확인해야 합니다. 브라우저에 API 키·Codex 인증 파일을 전달하지 않습니다. Windows 브라우저 사용에는 Linux 실행 서버가 적합하며 Windows 서버에서의 App Server 실행 검증은 별도 과제입니다.

## 5. 클라우드 배포 설계 (미수행)

Phase 1·2는 `npm ci && npm run build`로 생성한 `frontend/dist`를 정적 호스팅할 수 있습니다. 현재 페이지는 URL 라우팅을 사용하지 않으며 새로고침 시 시연을 초기화합니다. 공개용 환경 변수·키가 필요하지 않습니다.

실제 자동화 단계에는 HTTPS, 인증된 장기 WebSocket 연결, Node.js·Python·Codex 프로세스, 큐 재개를 지원하는 Linux 컨테이너/VM이 필요합니다. 일회성 정적 호스팅이나 짧은 서버리스 함수만으로는 이 실행 모델을 충족하지 못합니다. 초기에는 단일 인스턴스·제한 동시성을 사용하고 수평 확장 시 PostgreSQL·외부 큐·객체 저장소로 이전합니다.

- 인증: OIDC 세션, HttpOnly·Secure 쿠키, CSRF·Origin 검사, 조직/업무/파일 권한, WebSocket 연결·구독 권한 검증.
- 격리: 업무별 작업 디렉터리, 실행 사용자·네트워크·프로세스 제한, 파일 내용을 비신뢰 입력으로 취급, 매크로·임의 명령 실행 차단. 문서의 프롬프트 인젝션을 시스템 지시로 취급하지 않음.
- 저장소: 비공개 볼륨/객체 저장소, 암호화·보존 기한·삭제·백업/복원 검사, 단기 다운로드 URL. Git에 원본·DB·로그·개인정보 저장 금지.
- 비밀: 배포 플랫폼의 secret 저장소 사용. 프론트엔드 `VITE_*`에 자격 증명 금지. 조직별 인증 범위와 회수 절차 마련.
- 비용: 서버·볼륨·객체 저장소·백업·트래픽·AI 사용량을 각각 관리. 업무별 최대 파일 크기·시간·토큰·재시도·동시 실행 한도와 비용 상한 설정. 실제 가격 견적은 배포 시점 확인.
- 운영: 상태별 큐·에러·처리 시간 지표, 민감정보를 제거한 감사 기록, 장애·중단 복구, 알림, 데이터 삭제 요청 대응.

클라우드 개발 환경의 설치 스냅샷과 공개 웹앱 배포는 별개입니다. 개발 서버가 현재 떠 있다는 사실만으로 외부 배포·보안·상시 운영이 완료된 것은 아닙니다.

현재 첨부별 미리보기와 열 선택 저장 계약은 [미리보기 안내](FILE_PREVIEW.md)를 따릅니다. 이는 실제 집계·워커 실행 전의 준비 단계입니다.

선택 열의 전체 데이터 기초 집계는 [집계 기준](BASIC_SUMMARY.md)을 따릅니다. 미리보기와 집계는 같은 제한된 행 순회기를 사용하며, 원본 문자열은 집계 시 잘라서 합치지 않습니다. AI·워커 자동 실행은 별도 계획입니다.

## 현재 파일 집계 실행 큐

v6의 파일별 정량 집계는 API 서버가 관리하는 단일 Node worker_threads와 SQLite의 summary_runs / summary_run_events / summary_queue_lease를 사용합니다. 설정 스냅샷·원본 해시·상태 전이·소유권으로 결과 저장을 보호하고 완료된 요약 JSON을 보존합니다. Python/Codex 실행기는 아직 연결하지 않았으며 jobs의 접수 상태와 오피스 시뮬레이션은 변경하지 않습니다. 기존 CSV/HTML/XLSX는 현재 설정으로 계산하는 동기 다운로드입니다. 자세한 계약은 [백그라운드 집계 안내](BACKGROUND_SUMMARY.md)에 있습니다.

v7은 실행별 파일 메타데이터를 추가하고 완료 요약·메타데이터·이벤트를 한 트랜잭션으로 확정합니다. 파일의 fsync·검증·rename과 DB 확정 사이의 중단은 lease 획득 후 정리로 복구합니다. 다운로드는 현재 설정을 계산하지 않고 당시 파일 크기·해시·세션을 확인합니다. [실행 결과 파일 안내](RUN_ARTIFACTS.md)를 따릅니다.

v8은 실행당 한 번의 승인/반려와 대상 매니페스트를 summary_run_reviews에 보관합니다. 표시 결과와 파일 3종을 해시로 연결하고 무결성·세션·소유권·중복 결정을 검사합니다. jobs 접수 상태 및 시뮬레이션은 변경하지 않습니다. [결과 검토 안내](RESULT_REVIEW.md)를 따릅니다.

업무 목록/상세의 집계·검토 현황은 페이지·계정 범위의 SQL로 전체 진행 중 건수와 첨부별 최근 실행을 구분합니다. 파일 IO·결과 본문 조회 없이 메타데이터만 반환하고 승인 유효성은 결과 상세에서 재검증합니다. 스키마 v8을 유지합니다. [업무 현황 안내](JOB_ACTIVITY.md)를 따릅니다.
