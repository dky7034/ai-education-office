# AI 실행·검토 현황: 목록과 오피스

2026-10-26 기준, 업무 목록과 서버 오피스에 AI 텍스트 실행·검토의 읽기 전용 현황을 연결했습니다. 기본 AI 신규 접수/디스패치는 계속 비활성입니다. 표시 전환·조회·알림 때문에 AI를 호출하거나 검토 결정을 만들지 않습니다.

## 조회 범위와 API

업무 목록/상세의 job.aiActivity는 전체 진행 건수와 업무별 최근 AI 실행 하나를 반환합니다. 기존 job.activity의 정량 집계/파일 검토와 별개입니다. 목록 페이지의 업무 ID를 모아 한 SQL로 조회하며 업무마다 개별 결과를 읽지 않습니다. 기존 검색 상태 필터는 정량 집계 전용이며 AI 상태 필터는 아직 없습니다.

GET /api/jobs/ai-office는 로그인 계정 전체를 한 읽기 트랜잭션으로 조회합니다. 쿠키·계정 헤더를 확인하고 검색·페이지 등 모든 쿼리는 400입니다. 결과는 no-store입니다. 기존 GET /api/jobs/office는 정량 집계 전용 계약을 유지합니다.

- queued/running/cancelling: 업무별 최근 기록에 한정하지 않은 전체 진행 건수
- latestRuns: AI 기록이 있는 업무 수, 업무마다 최근 접수 시각·실행 ID 내림차순 하나를 선택
- completed/failed/cancelled/timedOut/interrupted: 업무별 최근 실행의 종료 상태 건수
- reviewPending/approved/rejected: 최근 완료 실행의 검토 기록 없음/승인 기록/반려 기록
- syntheticLatest/codexLatest: 최근 실행의 출처별 건수

대표 기록은 실행 중 → 중단 요청 → 대기 → 초안 검토 대기 → 최근 기록 순입니다. 같은 단계에서는 Codex 기록을 먼저 보고, 진행 기록은 접수 순, 종료 기록은 최근 순으로 정렬합니다. 최근 목록은 업무별 최신 기록 최대 5개입니다. 새 실행이 접수되면 과거 승인/반려는 최근 현황에서 빠지지만 원래 이력은 보존합니다. 오래된 진행 기록과 더 최근 종료 기록이 공존해도 진행 건수와 대표 후보에서 누락하지 않습니다.

조회 SQL은 AI 입력 snapshot·결과 본문·manifest·검토 의견·원본/출력 파일·인증 키를 읽거나 해시하지 않습니다. 승인/반려는 당시 기록의 존재만 뜻하며 현재 초안과 결정의 유효성은 상세에서 검사합니다. 검토 대기는 무결성까지 통과한 새 승인 가능성을 보증하는 값이 아닙니다. 소유권이 일치하지 않는 실행은 제외합니다. 조회 전후 상태·계정 이벤트 커서는 바뀌지 않습니다.

## 목록과 링크

각 업무에 AI 전체 대기/실행/중단 건수와 최근 실행·검토·출처를 정량 집계와 구분해 표시합니다. 합성 기록은 ‘실제 AI 호출 아님’으로 표시합니다. 최신 AI 실행 버튼은 기존 검색/업무 입력을 유지한 채 상세를 열고 job/aiRun URL을 갱신합니다. 해당 실행의 초안·검토를 볼 수 있으며 링크의 소유권 검사는 그대로 적용됩니다.

## 오피스 역할 표시

기존 ‘서버 집계 보기’에서 정량 집계 패널과 별도의 ‘AI 실행·검토 현황’을 함께 확인합니다. 두 API를 기존 계정 WebSocket tick으로 갱신하고 새 소켓을 만들지 않습니다. 하나의 조회가 실패해도 다른 종류의 정상 스냅샷을 실패로 바꾸지 않습니다.

정량 집계는 분석가에, 현재 지원하는 AI 텍스트 초안은 문서 전문가(작성가)에 표시합니다. 원래 업무 종류가 설문/PPT여도 이번 AI 실행은 파일 자동화가 아닌 텍스트 초안이므로 다른 전문 작업을 하는 것처럼 표시하지 않습니다.

- Codex 실행 기록은 기록 상태에 따라 작성/검토 대기/완료/오류 위치를 투영합니다. 제공자 연결을 직접 확인한 것이 아니므로 항상 ‘Codex 기록’이라고 표시합니다.
- 합성 기록은 출처와 상태를 보여 주되 작성가를 실제 작업 중으로 움직이지 않습니다.
- 팀장은 정량 집계와 AI 초안의 사용자 검토 대기 건수를 구분합니다. AI 수에는 합성도 포함하며 캐릭터가 승인하거나 반려하지 않습니다.
- AI 조회 실패·잘못된 응답·연결 단절/재생 중에는 작성가를 대기 위치와 ‘AI 기록 확인 필요’로 전환합니다. 마지막 목록/건수는 마지막 확인 기록으로 표시하고 복구 후 다시 투영합니다.
- 계정 변경/로그아웃 때 상위 오피스 데이터도 지웁니다. AI 스냅샷은 계정으로 구분해 다른 계정의 이전 응답을 표시하지 않습니다.

connectionVerified=false는 기록 조회가 AI 인증/모델 연결 성공을 증명하지 않는다는 뜻입니다. 오래된 Codex 기록이나 합성 데이터가 있다는 이유로 연결 상태를 성공으로 바꾸지 않습니다. 실제 서비스 인증·모델 호출 검증과 운영 정책은 후속 과제입니다.

## 검증과 제한

스키마 v11을 유지하며 새 테이블·마이그레이션은 없습니다. 합성 메타데이터와 별도 DB를 사용해 26개 업무·페이지 밖 계정 범위·다른 계정·과거 진행/새 종료 공존·검토 반영·원문 미조회·쓰기 없음·실패 복구를 검사합니다. Codex 역할 분기는 명시적인 합성 GET 응답으로 검증하고 실제 모델을 호출하지 않습니다. 단일 HTML은 계속 서버 없는 시연 전용입니다.
