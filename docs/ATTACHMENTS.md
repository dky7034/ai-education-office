# 업무 첨부 파일

로그인한 계정의 저장된 업무 상세에서 **첨부할 파일 → 파일 첨부**를 이용합니다. 목록은 새로고침·서버 재시작 후 복원됩니다. 원본 표시명, 크기, 저장 시각, 파일 ID와 SHA-256을 확인하고 다운로드할 수 있습니다. 업무와 첨부 보관만으로 AI나 집계는 실행되지 않습니다. 미리보기에서 열을 저장한 뒤 수동 기초 집계를 실행할 수 있습니다.

## 지원 범위

- 파일당 5MiB(5,242,880바이트), 업무당 5개. 한 번에 한 파일을 전송합니다.
- CSV: UTF-8(BOM 허용), 빈 파일·잘못된 UTF-8·바이너리 제어 문자·닫히지 않은 인용 필드 등을 거부합니다. 쉼표·세미콜론·탭 구분자를 첫 논리 행의 인용부호 밖에서 추정합니다. 임의 텍스트와 한 열짜리 CSV를 완전히 구분할 수는 없습니다. 업로드에서 열 개수·교육 데이터 의미는 검사하지 않습니다. 미리보기의 열·행 한도는 별도 적용합니다.
- XLSX: 일반적인 Excel OOXML 통합 문서. ZIP 항목 최대 1,000개, 압축 해제 합계 최대 20MiB. 크기·CRC, 필수 XML·통합 문서·워크시트 관계를 검사합니다. 통합 문서·관계·콘텐츠 유형 메타데이터 XML은 항목당 최대 512KiB입니다. 암호화 ZIP, 손상 XML, DTD·엔티티 선언, `vbaProject.bin`, 일반 ZIP 위장은 거부합니다. 워크시트가 없는 문서·차트 시트 전용 문서·Strict OOXML·UTF-16 XML은 현재 지원 범위 밖입니다.
- XLS·XLSM·DOCX·PPTX·PDF는 미지원입니다. 매크로·수식·외부 연결을 실행하지 않습니다. 파일 구조 검사는 악성코드 검사나 모든 Excel 기능의 완전한 유효성 검사를 대신하지 않습니다.

## API

모든 경로는 유효한 `office_auth` 세션이 필요합니다. 다른 계정의 업무·파일은 404, 세션 없음·전환된 계정 힌트는 401입니다. 오류에 내부 저장 경로를 포함하지 않습니다.

| 경로 | 용도 |
| --- | --- |
| `GET /api/jobs/:id/attachments` | `{ attachments: [...] }` |
| `POST /api/jobs/:id/attachments` | 원본 바이트 전송, 신규 201·동일 재전송 200 |
| `GET /api/jobs/:id/attachments/:fileId` | 소유자만 원본 다운로드 |

업로드 헤더: `Content-Type: application/octet-stream`, `X-Office-Request: 1`, `X-File-Name: encodeURIComponent(원본명)`, `Idempotency-Key: 영숫자·밑줄·하이픈 8~100자`. UI는 `X-Office-Account`로 입력 당시 계정도 확인합니다. JSON API와 같은 Origin 검사와 비캐시 정책을 적용합니다. 업로드 경로만 바이너리를 허용하며 일반 폼·multipart 요청은 받지 않습니다.

파일명은 최대 180자이며 제어 문자·경로 구분자를 거부합니다. 클라이언트 MIME은 파일 형식의 증거로 사용하지 않습니다. 전송 크기 초과는 413, 파일 검증 실패는 400, 개수 제한·식별자 충돌·원본 무결성 오류는 409입니다. 요청 식별자는 업무 범위이며 동일 이름·해시의 재시도는 한 파일만 저장합니다. 동일 파일이라도 새 식별자로 보내면 별도 첨부입니다.

## 저장·복구

SQLite v3는 기존 테이블을 보존하고 `attachments` 테이블만 추가합니다. 파일 ID·업무 ID·요청 식별자·표시명·형식·크기·SHA-256·저장 시각을 기록합니다. 계정 권한은 매번 업무 소유권에서 확인합니다.

기본 실제 서버는 `storage/input/jobs/<업무 UUID>/<파일 UUID>`에 원본을 보관합니다. `OFFICE_INPUT_DIR`로 저장 루트를 바꿀 수 있습니다. `createStore`를 직접 사용하는 별도 도구는 기본값으로 DB 옆 `attachments/`를 사용합니다. 표시명으로 경로를 만들지 않으며 원본을 수정·덮어쓰는 API는 없습니다. 새 업무 폴더 0700, 원본 0600으로 생성합니다. DB와 파일은 Git에서 제외하며 정적 웹 서버로 공개하지 않습니다.

파일 기록·fsync 후 DB 트랜잭션을 커밋합니다. 일반적인 저장 실패는 롤백·파일 정리하며 동시 요청에도 개수와 중복 제약을 유지합니다. 프로세스 강제 종료·전원 장애로 DB에 연결되지 않은 파일이 남을 수 있습니다. 자동 삭제는 하지 않습니다. 다운로드 전 크기·해시가 다르면 원본을 제공하지 않습니다.

백업은 DB만 복사하지 말고 **서버를 중지한 상태에서 SQLite와 첨부 저장 루트를 함께 보존**해야 합니다. DB·파일을 서로 다른 시점으로 복원하면 누락 또는 고아 파일이 생길 수 있습니다. 기존 원본을 임의로 수정하거나 테스트 파일을 기본 DB에 추가하지 마세요.

운영 배포의 전체 저장량·사용자별 할당량·전송 동시성·악성코드 검사·보존/삭제 정책은 후속 과제입니다. 현재는 로컬 개발용이며 실제 개인정보 파일을 넣지 않습니다. CSV 수식 등 내용은 원본 그대로 보존하므로 스프레드시트로 열 때 해당 프로그램의 보안 정책을 적용해야 합니다.

첨부 내용 미리보기와 분석할 열 선택 저장은 [미리보기 안내](FILE_PREVIEW.md)를 참고하세요.
