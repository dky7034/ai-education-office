# 업무 자동 갱신·연결 복구

업무 목록·선택한 상세의 집계/검토 현황과 열린 실행 목록·결과 검토 기록을 자동으로 갱신합니다. 다른 화면에서 업무를 접수하거나 집계를 접수/취소/완료하고 검토를 확정하면 같은 계정 화면에도 반영합니다. 캐릭터는 계속 시뮬레이션이며 AI 실행과 연결하지 않습니다.

## 화면 동작

- 연결 중/연결됨/재연결 중/오프라인과 목록을 마지막으로 성공적으로 확인한 시각을 표시합니다. 소켓 연결만으로 확인 시각을 갱신하지 않습니다. 실패 시 마지막 기록과 오류를 표시합니다.
- 적용한 검색·상태 조건과 URL을 유지합니다. 자동 갱신은 ‘더 보기’로 펼친 깊이까지 첫 페이지부터 다시 읽습니다. 마지막 페이지가 채워지거나 줄어들 수 있으며 더 보기 요청과 자동 읽기를 동시에 섞지 않습니다. 조건 변경이나 수동 상태 갱신은 기존처럼 첫 페이지로 돌아갑니다.
- 선택한 업무가 현재 필터 밖으로 나가도 상세·저장 결과를 유지합니다. 업무 작성, 미적용 검색어, 첨부할 파일 선택, 열/설문 편집, 검토 의견을 자동 갱신으로 초기화하지 않습니다. 다른 화면에서 결정이 확정되면 그 결정 기록으로 검토 폼을 대체합니다. 확인 체크는 검토 대상/유효성/결정이 바뀌면 해제합니다.
- 연결이 끊어지면 약 1·2·4·8·16·30초 간격(최대 30초 + 작은 임의 지연)으로 다시 연결합니다. 온라인 복귀·창 활성화·화면 복귀 시 최신 목록도 확인합니다. 응답이 35초 동안 없으면 소켓을 닫고 복구합니다. 목록·상세의 자동 조회와 검토 자동 조회에는 10초 제한을 적용합니다.
- 자동 갱신은 GET 조회만 수행합니다. 업무 저장·집계 접수·취소·검토 확정 등의 POST를 연결 복구로 재전송하지 않습니다. 해당 작업의 기존 명시적 재시도·중복 방지 계약은 유지합니다.
- 완료 요약 JSON은 열어 둔 당시 결과를 유지합니다. 검토 조회는 기존처럼 보관 파일의 무결성을 검사합니다. 원본 파일 목록·열/설문 설정 자체를 자동으로 덮어쓰지는 않습니다. 원본 파일 추가는 첨부 목록 새로고침으로 확인합니다. DB 외부의 파일 변조는 변경 알림 대상이 아니므로 파일/검토 조회 때 검사합니다.

## 전송·권한

`ws(s)://<현재 앱 호스트>/api/jobs/updates?account=<현재 계정 UUID>`

브라우저의 HttpOnly 로그인 쿠키와 현재 계정 UUID를 함께 검사합니다. UUID는 권한 증명이 아니며 URL에 세션 토큰을 넣지 않습니다. Origin은 요청 연결의 http/https와 Host를 조합한 값과 정확히 일치해야 합니다. Origin 없음/불일치는 403, 세션 없음·만료·계정 불일치는 401, 잘못된 쿼리는 400, 연결 상한 초과는 429로 업그레이드를 거부합니다. Vite는 Host를 보존하고 WebSocket을 프록시합니다.

서버가 보내는 메시지는 `{ "type": "snapshot", "revision": "<SHA-256>" }`뿐입니다. 제목·의견·파일 내용·세션 정보는 소켓으로 보내지 않습니다. 알림의 revision으로 권한을 얻지 않으며 실제 데이터는 기존 소유권 검사를 통과한 HTTP API로 다시 조회합니다. 클라이언트 메시지는 명령으로 처리하지 않고 1008로 닫습니다.

연결된 계정만 1초마다 읽기 전용 메타데이터 SQL로 확인하고 동일 계정의 소켓들은 그 결과를 공유합니다. 업무/첨부 개수·선택 버전 합계·최신 집계 이벤트 ID·검토 개수의 지문을 사용하며 기존 추가/버전 증가/불변 결정 계약을 전제로 합니다. 매번 세션을 재검사하고 만료·로그아웃·회수 후 소켓을 종료합니다. 메시지는 변경 시 또는 15초 확인 주기로 보내고 ping/pong·64KiB 송신 적체 제한을 적용합니다. 프로세스당 256개·계정당 8개 연결, 수신 메시지 1KiB 상한입니다. 서버 종료 시 타이머·업그레이드 리스너·소켓을 정리한 뒤 DB를 닫습니다.

## 복구 범위·제약

**이번 복구는 최신 스냅샷 재조회입니다. 개별 이벤트 영구 재생은 아직 구현하지 않았습니다.** 접속 직후에는 항상 지문을 보내므로 서버 재시작·연결 단절 중 여러 전환을 놓쳐도 최종 상태를 다시 읽습니다. 짧은 대기/실행 전환은 화면에 모두 보이지 않을 수 있으며 감사 이력은 기존 실행 이벤트 API/DB에서 확인합니다. 브라우저 메모리의 미제출 입력은 연결 복구 동안 유지하지만 새로고침·탭 종료 시 영구 복원하지 않습니다.

DB 스키마 v8을 유지하며 새 테이블/마이그레이션·사용자 데이터 변경이 없습니다. 대규모 계정/데이터의 성능, 전체 업무 상태 모델·캐릭터 연계, 영구 순서 이벤트/커서 재생은 후속 작업입니다. 현재 Origin 검사는 로컬 동일 호스트 연결·개발 프록시를 대상으로 합니다. TLS 종료 역방향 프록시의 신뢰할 외부 Origin/HTTPS 설정·다중 프로세스 운영·운영 배포는 별도 작업이며 임의 Forwarded 헤더를 신뢰하지 않습니다.
