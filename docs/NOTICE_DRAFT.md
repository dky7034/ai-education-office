# 목적·대상·핵심 내용으로 공지·메일 초안 작성

새 업무 요청에서 **공지·메일 작성 → 목적·대상·핵심 내용으로 작성**을 선택합니다. 제목과 초안 형식(공지/메일), 목적·대상·핵심 내용·선택 참고 메모를 입력해 저장합니다. 상세의 **공지·메일 초안 TXT 다운로드**로 규칙 기반 검수용 문서를 내려받습니다. AI 생성·발송·승인 기능이 아닙니다.

## 입력과 저장

| 항목 | 기준 |
| --- | --- |
| 제목 | 기존 업무 제목 기준 2~100자 |
| 형식 | notice(공지) 또는 email(메일) |
| 목적 / 대상 | 각각 필수 한 줄 1~300자 |
| 핵심 내용 | 필수 1~2,000자, 여러 줄 허용 |
| 작성자 참고 메모 | 선택, 최대 1,000자, 여러 줄 허용 |

문자 수는 기존 폼/API와 같은 UTF-16 단위입니다. 앞뒤 공백을 제거하고 CRLF/CR을 LF로 정규화하며 일부 제어/방향 문자를 거부합니다. 메모 생략은 빈 문자열로 정규화합니다. 알 수 없는 필드는 거부합니다. 별도의 수신자 주소·API 키·모델·발송 옵션 필드는 받지 않습니다. 실제 개인정보·비밀은 넣지 않습니다.

`POST /api/jobs`는 기존 자유 요청 `{kind,title,instructions}`와 구조화 공지 `{kind:"notice",title,notice:{format,purpose,audience,keyPoints,notes?}}`를 지원합니다. 두 방식의 instructions와 notice를 함께 보내거나 다른 업무 종류에 notice를 지정하면 400입니다. 구조화 필드로 검색/요청 내용에 사용할 표준 텍스트를 서버가 생성합니다. 제목·목적·대상·핵심·메모를 기존 검색에서 찾을 수 있습니다.

스키마 v12는 jobs에 nullable notice_json 열 하나만 추가합니다. 기존 행은 null이고 자유 입력 업무를 구조화 요청으로 추측하거나 변환하지 않습니다. 기존 내용·요청 해시·계정·이력·집계·AI/검토 테이블을 재작성하지 않습니다. API 응답은 구조화 업무에만 notice를 포함합니다. 동일 요청 키의 중복 방지는 정규화한 구조화 입력도 해시에 포함하며 같은 입력은 기존 업무를 반환하고 변경된 내용은 409입니다. 업무/구조화 입력/접수 이력·계정 이벤트는 같은 트랜잭션입니다.

저장된 요청은 현재 업무 모델처럼 수정하지 않습니다. 변경이 필요하면 새 요청으로 저장합니다. 폼의 구조화 입력/자유 입력 전환은 각각의 미제출 입력을 유지하고, 저장 실패 시 입력·같은 요청 키를 유지해 명시적으로 재시도합니다. 성공 시 신규 요청 입력은 비웁니다. 미저장 입력을 새로고침 뒤 복구하는 기능은 제공하지 않습니다. 저장한 구조화 입력은 새로고침/동일 계정 재로그인 후 상세에서 복원합니다.

## 초안 다운로드

`GET /api/jobs/:jobId/notice-draft`는 로그인한 소유자의 구조화 notice 업무에만 허용합니다. 미로그인/다른 계정 헤더는 401, 다른 계정/없는 업무는 404, 쿼리 조건은 400, 기존 자유 요청이나 다른 종류의 업무는 409입니다. 인증·계정 소유권·no-store·nosniff를 적용합니다.

파일은 UTF-8 BOM·CRLF·text/plain attachment, `office-notice-<jobId>.txt`, 최대 32KiB입니다. 제목은 한 줄로 정리하고 입력 내용은 일반 텍스트로만 출력합니다. HTML/EML/mailto 링크를 만들지 않습니다. 공지는 안내 문구, 메일은 인사말을 붙이고 목적·대상·핵심 내용을 그대로 배치합니다. 입력하지 않은 날짜·장소·마감·연락처를 추정하지 않습니다. 참고 메모는 본문으로 자동 반영하지 않고 공유 전 삭제/반영 여부를 확인할 별도 부분으로 표시합니다.

문서는 검수 필요·규칙 기반·AI 생성 아님·발송하지 않음을 명시합니다. 내용에 대한 사실 검증·문맥 해석·자동 문장 교정은 하지 않습니다. 목적·공유 범위·개인정보·날짜·참고 메모를 직접 검수한 뒤 파일을 수정해 사용합니다. 승인/발송 기록이 아니며 업무 ID·저장 시각을 근거로 남깁니다.

다운로드는 동기 메모리 생성이며 DB/파일·상태/이벤트·AI 실행/검토 기록을 쓰지 않습니다. 저장이 같으면 같은 파일을 반환합니다. 실패 후 다시 다운로드할 수 있고 새로운 업무 입력은 유지합니다. 계정/업무 전환 때 이전 패널의 요청을 중단하고 늦은 응답을 버립니다.

제품용 AI가 별도 활성화된 계정에서 사용자가 AI 초안 접수를 명시적으로 선택하면 기존 AI 계약에 따라 구조화 입력을 포함한 저장 요청 내용이 제공자에게 전송될 수 있습니다. 이 TXT 기능이나 업무 저장만으로 AI 호출이 시작되지는 않습니다.
