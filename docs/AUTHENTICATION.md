# 계정·업무 권한·이력 복구

## 사용자 흐름

1. 백엔드와 함께 실행한 앱의 ‘계정·이력 복원’에서 회원가입합니다. 아이디는 영문으로 시작하는 영문·숫자·밑줄 3~32자이며 공백 제거·소문자 정규화를 적용합니다. 비밀번호는 12~128자입니다.
2. 회원가입 직후 한 번 표시하는 복구 코드를 아이디와 함께 안전한 곳에 따로 보관합니다. 앱은 원래 코드를 다시 조회하는 API를 제공하지 않습니다.
3. 로그인하면 해당 계정의 업무만 생성·조회합니다. 다른 브라우저에서 같은 계정으로 로그인하면 같은 이력을 읽습니다. 새 브라우저에서도 업무 요청·이벤트·원래 ID는 유지됩니다.
4. 비밀번호를 잊으면 ‘비밀번호 복구’에 아이디·복구 코드·새 비밀번호를 입력합니다. 코드는 한 번 사용하고 새 코드로 교체합니다. 기존 로그인은 모든 브라우저에서 무효화되므로 다시 로그인합니다.
5. 코드를 잃었지만 현재 비밀번호를 알면 로그인 후 ‘복구 코드 재발급’을 사용합니다. 현재 비밀번호 확인 후 새 코드를 발급하며 이전 코드는 무효가 됩니다.

이메일·휴대전화 인증은 없습니다. 비밀번호와 복구 코드를 모두 잃으면 자동 계정 복구를 제공하지 않습니다. 복구 코드·비밀번호를 채팅·로그·스크린샷·Git에 공유하지 마세요. 브라우저 저장소에 앱이 비밀번호나 복구 코드를 따로 보관하지 않습니다.

## 기존 브라우저 이력 가져오기

DB v1의 기존 업무·이벤트·세션은 삭제하지 않습니다. v2는 계정 테이블과 계정 소유권 열·인덱스를 추가합니다. 기존 요청의 계정은 처음에는 비어 있습니다.

이전 `office_session` 쿠키가 유효한 브라우저에만 기존 업무 건수를 보여줍니다. 회원가입·로그인만으로 자동 이전하지 않습니다. 본인의 업무인지 확인한 후 ‘기존 이력 가져오기’를 누르면 현재 계정에 한 번 연결합니다. 이후 원래 쿠키가 만료돼도 같은 계정으로 로그인해 읽을 수 있습니다.

원래 업무 ID·내용·접수 시각·이벤트·브라우저 소유자 참조를 보존합니다. 이전된 요청의 내부 중복 방지 키만 예약된 `legacy:` 공간으로 옮겨 새 계정 요청과 충돌하지 않게 합니다. 이미 이전된 업무는 다른 계정이 같은 쿠키로 다시 가져갈 수 없습니다.

기존 쿠키를 삭제했거나 만료시킨 경우 익명 이력의 소유자를 확인할 수 없어 임의로 계정에 연결하지 않습니다. 기록은 DB에 남아 있지만 새로운 계정의 이력으로 자동 노출하지 않습니다. 공용 브라우저의 기존 이력을 본인 것으로 단정하지 마세요.

## 인증 API

쓰기 요청은 `Content-Type: application/json`, `X-Office-Request: 1`과 같은 사이트의 Origin을 요구합니다. 인증·업무 응답은 `Cache-Control: no-store`를 적용합니다.

| API                             | 입력·동작                                                                                                  |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `GET /api/auth/session`         | `{ user: { id, username, createdAt } 또는 null, legacyCount }`                                             |
| `POST /api/auth/register`       | `username`, `password`. 계정 생성·로그인, `201` 및 한 번 표시할 `recoveryCode`                             |
| `POST /api/auth/login`          | `username`, `password`. 세션 교체, 공개 계정 정보 반환                                                     |
| `POST /api/auth/logout`         | 빈 JSON. 현재 세션만 서버에서 회수하고 쿠키 삭제                                                           |
| `POST /api/auth/recover`        | `username`, `recoveryCode`, 새 `password`. 비밀번호 변경·전체 세션 회수·새 코드 발급. 자동 로그인하지 않음 |
| `POST /api/auth/renew-recovery` | 로그인 및 현재 `password`. 코드 재발급, 이전 코드 무효화                                                   |
| `POST /api/auth/import-legacy`  | 로그인 및 유효한 기존 브라우저 쿠키. `{ imported: 건수 }`                                                  |

로그인 없이 업무 목록·상세·이벤트·저장을 요청하면 `401`, 다른 계정의 ID를 조회하면 존재하지 않는 ID와 같은 `404`를 반환합니다. 클라이언트는 `X-Office-Account`에 화면의 계정 ID도 보내며 실제 로그인과 다르면 `401`로 차단합니다. 다른 탭에서 계정이 바뀐 뒤 이전 화면 내용이 새 계정에 저장되는 것을 방지합니다.

계정이 바뀌거나 로그아웃하면 화면의 업무·선택 ID·입력·복구 코드 상태를 제거합니다. 포커스·가시성 변경 시 로그인 상태를 다시 확인하며 DB 업무를 삭제하지 않습니다. 로그아웃 뒤 과거 토큰으로 API에 접근할 수 없습니다.

## 저장·보안 구현

- 비밀번호는 Node.js 비동기 scrypt로 해시합니다. N=32768, r=8, p=3, 16바이트 무작위 salt, 64바이트 결과를 사용하며 버전·비용 값과 함께 저장합니다. 비교는 `timingSafeEqual`을 사용합니다. 알 수 없는 아이디도 더미 해시 검증을 거쳐 로그인 실패 문구를 동일하게 제공합니다.
- 복구 코드는 32바이트 난수이며 정규화한 값의 SHA-256 해시만 DB에 저장합니다. 코드 사용 시 DB의 이전 해시를 조건으로 원자적으로 교체해 동시 요청 두 건이 함께 성공하지 않게 합니다.
- 세션은 32바이트 난수의 `office_auth` 쿠키입니다. DB에는 해시만 저장하고 7일 후 만료합니다. HttpOnly·SameSite=Strict·Path=/api, 운영 모드는 Secure를 적용합니다. 만료 후 다시 로그인하면 업무는 복원됩니다.
- 회원가입·로그인 시 기존 현재 세션을 회수하고 새 토큰을 발급합니다. 다른 브라우저의 정상 세션은 유지하며 비밀번호 복구 시에는 모두 회수합니다. FK 보존을 위해 세션 행을 삭제하지 않고 만료 시각을 변경합니다.
- 로그인·가입·복구·재발급 시도는 단일 프로세스 메모리에서 15분당 아이디 30회·IP 300회로 제한합니다. 버킷 수와 키 길이도 제한합니다. `429`와 `Retry-After`를 반환하며 분산·영속 제한은 아직 없습니다.
- 요청 본문·쿠키·비밀번호 해시·복구 코드는 서버 콘솔에 출력하지 않습니다. 다른 계정의 소유권 필드나 비밀 값은 공개 API로 반환하지 않습니다.

## 운영 전 남은 일

기본 로컬 계정과 소유권 검사를 구현했으며 공개 운영 배포를 완료한 것은 아닙니다. 실제 배포에는 HTTPS, `NODE_ENV=production`, 프록시 Host 보존, 등록 정책·본인 확인, 조직 권한, 분산 시도 제한, 감사·보존·삭제·백업/복원 정책, 보안 점검이 필요합니다. 현재 DB는 암호화되지 않았고 조직·관리자 권한, 이메일 인증, 2단계 인증은 없습니다. 실제 교육생 개인정보·파일 처리는 아직 연결하지 마세요.
