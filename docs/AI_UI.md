# AI 텍스트 초안·실행 이력 화면

로그인한 뒤 저장된 업무를 선택하면 업무 상세에 **AI 텍스트 초안·실행 이력** 패널이 표시됩니다. 기존 정량 집계·파일 검토·오피스 시연과 별개입니다. 기본 서버는 AI 실행 미설정이며 접수 버튼이 비활성입니다. 이 화면을 추가하면서 실제 AI 호출을 활성화하지 않았습니다.

## 조회와 결과

- 업무별 실행 기록을 20개씩 조회하고 이전/다음 페이지로 이동합니다. 대기·실행·중단 요청·완료·실패·취소·시간 초과·실행 결과 확인 필요를 구분합니다.
- 합성 실행 기록은 ‘실제 AI 호출 아님’으로 표시합니다. Codex 접수 설정이 있다는 사실도 인증 유효성이나 모델 호출 성공을 의미하지 않습니다.
- 실행을 선택하면 상태 이력과 완료된 초안을 확인합니다. 결과는 AI 생성 초안이며 [검토 패널](AI_REVIEW.md)에서 사용자 승인·반려를 별도로 기록합니다. 발송·파일 반영 기능은 없습니다. 정량 집계의 기존 승인 기록을 AI 초안에 적용하지 않습니다.
- 생성 본문은 HTML/Markdown 실행 없이 일반 텍스트로 표시합니다. 응답의 출처·검수 필요 플래그·UTF-8 16KiB 한도·SHA-256을 확인합니다. 해시는 내용의 정확성이나 사람이 승인했다는 증명이 아닙니다. 브라우저의 Web Crypto를 사용할 수 있는 HTTPS/localhost 환경이 필요합니다.
- 선택한 실행은 `job`/`aiRun` URL로 복원합니다. 페이지를 바꾸거나 검색 조건을 갱신해도 열린 초안을 유지합니다. 이 URL은 공개 공유 링크가 아니며 같은 계정의 업무 권한이 필요합니다. 다른 업무 선택·로그아웃·계정 변경 때 이전 실행 선택을 제거합니다.

## 접수와 취소

서버 운영자가 [AI 큐 설정](AI_QUEUE.md)을 등록한 경우에만 텍스트 초안 접수를 활성화합니다. Codex 설정에서는 저장된 업무 요청의 제공자 전송과 사용료 가능성을 안내합니다. 입력은 서버가 접수 당시 저장한 업무에서 가져오며 첨부 파일은 전송하지 않습니다. 신규 업무 입력 폼의 아직 저장하지 않은 초안은 AI 입력에 사용하지 않습니다.

접수는 사용자가 버튼을 눌렀을 때만 POST로 전송합니다. 응답 유실/통신 오류/10초 응답 시간 초과 때 요청 키를 유지하고 ‘접수 응답 다시 확인’을 제공합니다. 사용자가 이를 누르면 같은 키를 재사용합니다. 서버의 기존 기록은 같은 실행으로 복구합니다. 이 키는 현재 패널 수명 내에서만 유지하며 새로고침 뒤에는 이력을 먼저 확인해야 합니다. 조회·재연결·URL 복원·오피스 표시 때문에 접수나 AI 호출을 재전송하지 않습니다.

대기는 즉시 취소하고 실행 중에는 중단 요청을 접수합니다. cancelling은 원격 취소 확정이 아닙니다. 원격 interrupted 확인, 완료와 취소 경합, 중단 미확정, 서버 재시작 후 실행 미확정을 구분합니다. 미확정 작업은 자동 재실행하지 않으며 재접수 전에 원격 실행 여부를 확인해야 합니다. Codex 사용료가 이미 발생했다면 취소로 없어지지 않을 수 있습니다. 합성 기록에는 사용료 발생을 주장하지 않습니다.

## 갱신·오류·권한

기존 업무 WebSocket의 계정별 알림/재연결 tick을 공유하며 별도 소켓을 만들지 않습니다. 표시된 대기·실행·중단 중 기록은 2초 간격의 GET으로도 확인합니다. 이력 새로고침·알림은 검색 입력·열린 결과를 지우지 않습니다.

목록 조회 실패/잘못된 응답 때 현재 접수 설정을 신뢰하지 않고 신규 접수를 잠급니다. 네트워크 오류의 이전 기록/초안은 마지막 확인 결과로 남기고 재확인 필요를 표시합니다. 결과 형식·해시·출처 오류 또는 서버의 무결성 거부 때는 해당 초안을 제거합니다. 권한 거부는 목록과 초안을 즉시 지우며 먼저 시작했던 조회의 늦은 성공 응답도 다시 표시하지 않습니다. 401은 기존 계정 갱신 경로로 처리합니다.

계정/업무 전환 시 컴포넌트와 AbortController를 정리하고 서로 다른 업무의 응답·POST 결과를 적용하지 않습니다. 목록/상세/접수/취소의 응답 형식과 업무/실행 ID를 확인합니다. 같은 범위의 권한 변경도 별도 세대로 구분합니다. 실패 후 다시 시도는 조회이며 POST 자동 재생이 아닙니다.

## 검증 범위와 남은 작업

검사는 별도 E2E DB의 명시적인 합성 기록과 합성 HTTP 응답을 사용합니다. 실제 모델이나 서비스 인증 키를 사용하지 않습니다. 기본 비활성, 페이지/URL/계정 격리, 실제 API 취소와 합성 원격 종료, 응답 유실 후 같은 키 재확인, 텍스트 안전성·좁은 화면, 잘못된 200 응답, 권한 거부 뒤 늦은 응답을 확인합니다.

DB 스키마 v11에 AI 검토 기록을 추가했습니다. 운영 서비스 인증·비용/데이터 정책·실제 호출 검증, 파일 산출물 검증, AI 상태의 오피스 캐릭터 연결은 후속 작업입니다.
