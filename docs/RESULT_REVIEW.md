# 실행 결과 검토·승인

완료된 실행의 **저장된 집계 결과 보기**에서 요약과 보관 CSV·HTML·XLSX를 확인한 뒤 **결과물 검토·승인**을 사용합니다. 승인 또는 반려를 선택하고, 확인 체크 후 결정을 확정합니다. 검토 의견은 최대 2,000 UTF-16 단위이며 반려 사유는 필수입니다. 앞뒤 공백은 UI에서 제거합니다.

결정은 해당 계정이 소유한 실행당 한 번 기록합니다. 승인자 계정 ID·결정 시각·의견·검토 대상 SHA-256을 표시하고 새로고침/재로그인/서버 재시작 후 복원합니다. 승인과 반려는 같은 수준의 최종 결정이며 수정·철회 API는 없습니다. 다시 검토하려면 수정 설정으로 새 집계를 접수하세요. 새 실행에 과거 결정이 자동 적용되지 않습니다.

이 기능은 교육 운영자가 결과물을 확인했다는 기록입니다. 업무 접수 상태(received/not_connected), 오피스 시뮬레이션, 집계 실행 완료 상태를 바꾸지 않습니다. 외부 발송·캘린더 변경·AI 실행을 시작하지 않으며 조직별 결재선/복수 검토자 기능은 포함하지 않습니다.

## 승인 대상과 무결성

검토 대상 해시는 실행·업무·첨부 ID, 저장 요약 JSON의 SHA-256, 정렬된 파일 3종의 형식·크기·SHA-256·생성 시각으로 구성한 매니페스트의 SHA-256입니다. 화면이 연 저장 결과의 해시와 검토 API의 해시가 같아야 새 결정을 확정할 수 있습니다. CSV·HTML·XLSX 모두 존재하고 크기·해시·일반 파일 검사를 통과해야 하며 심볼릭 링크는 거부합니다. 파일 없는 이전 완료 작업과 대기/실행/실패/취소 작업은 확정할 수 없습니다.

서버는 파일 검사 후 세션을 다시 확인하고 트랜잭션 안에서 대상 해시·소유권·기존 결정을 재검증합니다. 원본/현재 설정의 이후 변경은 당시 보관 결과의 승인을 바꾸지 않습니다. 저장 요약·파일 메타데이터가 달라지거나 파일이 손상·분실되면 기존 결정 기록을 보존하면서 현재 파일에 유효하지 않다고 안내합니다. 원래 바이트와 메타데이터로 복원되면 동일 대상에 대한 유효성을 다시 확인할 수 있습니다. 파일과 DB가 하나의 OS 트랜잭션은 아니므로 임의 디스크 변경을 영구적으로 막는 전자서명 시스템은 아닙니다. 조회/신규 결정 시점의 무결성 확인입니다.

v8은 `summary_run_reviews`를 추가하며 기존 계정·업무·원본·완료 결과·파일 메타데이터를 유지합니다. 결정 행 자체가 변경 불가능한 검토 이력입니다. 실행별 고유 제약과 계정별 요청 키 고유 제약이 중복 결정을 방지합니다. 매니페스트도 결정과 같은 트랜잭션으로 보관합니다. 검토 의견에도 업무 정보가 들어갈 수 있으므로 DB·입력·출력·백업을 비공개로 보관하세요.

## API

접두사: `/api/jobs/:id/attachments/:fileId/runs/:runId`.

| 요청 | 계약 |
| --- | --- |
| GET `/result` | 기존 응답에 `reviewTargetHash`를 추가. 표시 결과와 검토 대상을 연결 |
| GET `/review` | `{ targetHash, reviewable, problem, decision }`. 파일 무결성을 확인하며 decision은 null 또는 결정 기록+valid |
| POST `/review` | `{ targetHash, decision: "approved" 또는 "rejected", comment }`, `Idempotency-Key` 필요. 신규 201·같은 요청 재전송 200 |

쓰기에는 동일 Origin·JSON·X-Office-Request: 1이 필요하며 UI는 X-Office-Account를 전송합니다. 세션/계정 전환 실패 401, 다른 소유자·업무·첨부·없는 실행 404, 본문/키/사유 오류 400, 미완료·손상/없는 파일·대상 변경·이미 다른 결정 확정·키 충돌 409입니다. no-store·nosniff를 유지합니다.

같은 요청 키와 같은 실행·해시·결정·의견을 재전송하면 기존 영수증을 반환합니다. 확정 응답이 유실된 뒤 파일이 분실되어도 동일 결정 영수증은 재조회할 수 있으며, 현재 유효성은 GET `/review`로 다시 확인합니다. 다른 요청의 같은 키 또는 다른 키로 이미 결정한 실행을 재확정할 수 없습니다. UI는 연결 실패 시 같은 요청 키를 유지하고 409에서는 최신 결정을 불러옵니다. 파일 오류를 검토 화면 새로고침으로 재확인할 수 있으며 보관 파일을 덮어쓰거나 새로 생성하지 않습니다.
