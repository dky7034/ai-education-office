# 업무 검색·집계/검토 상태 필터

업무 목록의 **업무 검색·상태 필터**에서 검색어와 상태를 선택하고 **검색·필터 적용**을 누릅니다. 제목 또는 요청 내용에 검색어가 포함된 업무를 찾습니다. 검색어와 상태를 함께 지정하면 두 조건을 모두 만족하는 업무를 표시합니다. **검색·필터 초기화**로 전체 목록을 다시 엽니다.

검색은 입력한 구문 그대로의 포함 검색입니다. 앞뒤 공백을 제거하고 영문 ASCII 대소문자를 구분하지 않습니다. `%`, `_`, 따옴표는 일반 문자입니다. 검색어는 최대 100 UTF-16 단위이며 입력 원본·결과 파일 본문·검토 의견은 검색 범위에 포함하지 않습니다.

## 상태 기준

| 화면 / API status | 해당 업무 |
| --- | --- |
| 전체 / all | 상태 조건 없이 조회 |
| 집계 이력 없음 / none | 집계를 접수한 이력이 없음 |
| 집계 대기 / queued | 전체 실행 중 대기 작업이 하나 이상 |
| 집계 실행 중 / running | 전체 실행 중 처리 중인 작업이 하나 이상 |
| 최근 집계 완료 / completed | 첨부별 최근 실행 중 완료가 하나 이상 |
| 최근 집계 실패 / failed | 첨부별 최근 실행 중 실패가 하나 이상 |
| 최근 집계 취소 / cancelled | 첨부별 최근 실행 중 취소가 하나 이상 |
| 검토 대기 / review_pending | 최근 완료 실행에 파일 메타데이터 3종이 있고 검토 결정이 없는 첨부가 하나 이상 |
| 승인 기록 / approved | 첨부별 최근 실행에 승인 기록이 하나 이상 |
| 반려 기록 / rejected | 첨부별 최근 실행에 반려 기록이 하나 이상 |
| 요약만 보관 / summary_only | 최근 완료 실행에 검토 결정과 파일 메타데이터 3종이 없는 첨부가 하나 이상 |

첨부별 최근 실행은 접수 시각·실행 ID 내림차순으로 결정합니다. 예전 승인 후 새 실행을 접수하면 그 첨부는 새 실행의 상태로 판별합니다. 파일이 여러 개면 같은 업무가 승인 기록·검토 대기 등 여러 조건에 해당할 수 있습니다. 대기/실행 중에는 과거 실행도 포함하므로 최근 실행이 취소된 업무가 실행 중 필터에도 나타날 수 있습니다.

승인·반려 필터는 당시 결정 기록을 찾습니다. 목록과 필터에서는 파일을 읽지 않으며 무결성·현재 결정 유효성은 [결과 상세](RESULT_REVIEW.md)에서 확인합니다.

## 페이지·화면 유지·복원

서버가 해당 계정의 전체 업무에 검색·상태 조건을 적용한 뒤, 기존 업무 접수 시각·ID 내림차순으로 페이지를 나눕니다. 화면의 총건수와 **이력 더 보기**도 같은 조건을 사용합니다. 조건 변경·상태 새로고침은 첫 페이지부터 다시 조회합니다. 서버의 다른 쓰기로 목록 순서나 해당 상태가 바뀌면 [자동 갱신](JOB_UPDATES.md)으로 현재 조건·더 보기 깊이를 유지하며 다시 조회합니다.

검색·필터를 적용해도 열어 둔 업무·결과·검토 의견은 유지합니다. 선택한 업무가 현재 표시 목록 밖이면 안내합니다. 예를 들어 검토 대기 필터에서 승인하면 그 업무는 목록에서 빠지고 승인된 상세 결과는 그대로 남습니다. 상태 새로고침·더 보기·검토 후 현황 갱신에도 적용한 조건을 유지합니다.

다른 조건을 조회하다 실패하면 이전 조건의 목록을 표시하지 않고 건수를 ‘—’로 표시합니다. 같은 조건의 조회 실패는 마지막 목록을 유지하고 오류를 안내합니다. **다시 연결**이나 다시 적용으로 재시도하며 열어 둔 상세·검토 의견·선택해 둔 첨부 파일을 유지합니다. 기존 **이력 새로고침**은 상세 전체를 다시 불러오는 기능입니다. 늦게 도착한 이전 조건/더 보기 응답은 새 목록에 합치지 않습니다.

적용 조건은 URL의 `q`, `status`에 저장하며 기존 `job`, `file`, `run` 결과 링크를 유지합니다. 새로고침/같은 계정 재로그인 시 검색·필터와 선택한 결과를 복원합니다. 빈 검색어와 전체 상태는 URL에서 제거합니다. 화면은 지원하지 않는 URL 상태 값을 전체로 엽니다. 다른 계정으로 URL을 열면 그 계정의 검색 결과와 접근 권한을 적용합니다.

## API

`GET /api/jobs?limit=20&offset=0&q=합성&status=review_pending`

- q: 선택 문자열, 기본 빈 검색어. 공백 제거 전 100 UTF-16 단위 이하이며 C0/DEL 제어 문자를 거부합니다. 유효한 입력의 앞뒤 공백을 제거합니다.
- status: 표의 값 중 하나, 기본 all.
- limit: 1~100 정수, 기본 20. offset: 0 이상 안전 정수, 기본 0.
- 허용 키는 limit/offset/q/status이며 잘못된 값·중복·객체/배열·알 수 없는 키는 400입니다.

응답은 `{ jobs, page: { total, limit, offset, hasMore }, filters: { q, status } }`입니다. total은 두 조건을 적용한 전체 건수이며 빈 페이지도 같은 total을 반환합니다. 세션·계정 전환·소유권·no-store·nosniff를 유지합니다.

검색·상태는 매개변수를 바인딩한 SQL로 적용합니다. 첨부별 최신 실행과 검토 분류는 [업무 현황](JOB_ACTIVITY.md)과 같은 기준이며 페이지를 잘라낸 뒤 클라이언트에서 거르지 않습니다. 검색 조회는 스키마 v9에서도 원본·결과·업무·검토 데이터를 변경하지 않습니다. 검색 순위/형태소 분석·전체 문서 검색·복수 상태 동시 선택은 후속 작업입니다. 계정별 WebSocket 알림과 최신 스냅샷 복구는 [자동 갱신 안내](JOB_UPDATES.md)를 따릅니다.
