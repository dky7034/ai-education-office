# 제품용 AI 연결 점검

제품 키와 운영 정책이 준비된 Linux 호스트에서 단일 텍스트 호출을 점검하는 운영자 명령입니다. 기본 서버·HTTP 접수·큐 디스패치는 계속 비활성입니다. 이 명령은 업무 DB·사용자 입력·첨부 파일을 사용하지 않습니다. 자동 실행·재시도·로그인은 없습니다.

## 준비

Node.js 24 이상과 신뢰할 수 있는 Codex CLI **0.163.0**을 별도로 준비합니다. CLI를 자동 설치하지 않습니다. [설정 예시](../config/ai-service.example.json)를 저장소 밖의 비공개 디렉터리에 복사하고 권한을 0600으로 지정합니다. 제품 키는 다른 0600 파일에 비밀 저장소를 통해 주입합니다. 키를 채팅·명령 인수·설정 JSON·Git·로그에 넣지 않습니다. 개발용 Codex 로그인과 부모 환경의 OPENAI_API_KEY는 사용하지 않습니다.

| 필드 | 기준 |
| --- | --- |
| version | 정수 1 |
| executable | 운영자가 신뢰하는 CLI 실행 파일의 절대 경로 |
| serviceApiKeyFile | 제품 키 파일의 절대 경로 |
| model | 이용 가능한 승인 모델명, 영숫자·점·밑줄·하이픈 1~100자 |
| maxRunMs | 초기화·인증·응답을 포함한 50~120,000ms 정수 |
| allowPaidCalls | 서비스 계정·제공자 측 비용 제한·사용량 확인 후 true |
| allowDataTransfer | 제공자 이용·데이터 전송/처리/보존 조건 확인 후 true |
| executionIsolationReviewed | 실제 호출 호스트의 격리·파일/네트워크 접근 범위 검토 후 true |

예시의 확인 항목은 false입니다. 운영 검토를 마친 항목만 true로 바꿉니다. 프로그램은 이 확인이 실제로 수행됐는지 증명하지 않습니다. 설정/키 파일은 현재 유효 사용자 소유, 정확히 0600인 일반 파일이어야 하며 마지막 경로의 심볼릭 링크·하드 링크·디렉터리·FIFO를 거부합니다. 상위 디렉터리와 바이너리의 신뢰성은 호스트 운영자가 관리합니다. 설정 8KiB, 키 4KiB 제한이며 키 끝의 한 개 개행(LF/CRLF)만 허용합니다. 알 수 없는 설정 필드는 거부합니다. 키·파일 경로·원격 오류는 오류 메시지에 복사하지 않습니다.

## 기본: 호출 없는 오프라인 검사

```sh
OFFICE_AI_CONFIG=/secure/office/service.json npm run check:ai
```

설정 형식·확인 항목·비공개 파일·키 형식·실행 파일 존재/실행 권한만 검사합니다. 자식 프로세스를 시작하지 않아 버전 명령·인증·네트워크·모델 호출이 없습니다. 성공은 **설정 검사 통과**이며 유효한 인증·모델 접근·바이너리 진위·격리 실효성을 증명하지 않습니다. 오류/설정 누락은 종료 코드 1, 검사 통과는 0입니다. `OFFICE_AI_CONFIG`만 명시적인 설정 경로로 사용하며 다른 인증 환경 변수로 대체하지 않습니다.

AI 호출 없는 실제 CLI 버전·stdio 초기화·미인증 계약 검사는 별도로 제공하는 `OFFICE_CODEX_BIN=/absolute/path/to/codex npm run check:codex`를 사용합니다. 두 명령의 검사 범위는 다릅니다.

## 명시적 단일 호출

```sh
OFFICE_AI_CONFIG=/secure/office/service.json npm run check:ai -- --execute
```

이 명령은 실제 인증·모델 호출을 시도하며 비용이 발생할 수 있습니다. 고정된 가상 교육 A 응답 3개(만족 2·보통 1)를 한국어 한 문장으로 요약하도록 요청합니다. 임의 프롬프트·모델·키를 명령 인수로 받지 않습니다. 미지정·추가 인수는 거부하고 호출하지 않습니다.

[기존 실행 어댑터](CODEX_ADAPTER.md)의 격리된 임시 HOME/CODEX_HOME/cwd, stdio 키 전달, 승인 요청 거부·읽기 전용 정책·도구 item 거부·시간 제한을 사용합니다. **이 정책만으로 호스트 전체 격리가 보장되지는 않습니다.** 검토된 실행 호스트에서만 실제 호출합니다.

한 프로세스에서 turn/start를 최대 한 번 보내며 새 실행 식별자를 사용합니다. 종료 때 자식과 임시 디렉터리를 정리합니다. SIGINT/SIGTERM은 어댑터 취소로 연결하며 원격 interrupted 확인과 unknown을 구분합니다. 강제 종료는 원격 취소나 과금 중단을 증명하지 않습니다. 자동 재전송은 없지만 명령을 다시 실행하면 새 호출이 됩니다. 결과가 모호하거나 실패했다면 제공자 사용량을 먼저 확인합니다. App Server 자체 재시도는 존재할 수 있으며 실행 시간은 금액 상한이 아닙니다.

출력은 성공 여부·상태·원격 상태와 검수 필요 안내뿐입니다. 키·생성 문장·프롬프트·실행/thread/turn ID·원격 오류를 출력/저장하지 않습니다. 정상 종료+비어 있지 않은 final_answer+검수 플래그와 정리 완료를 성공으로 취급하며, 문장의 사실성이나 수치 정확성을 보증하지 않습니다. 실패·취소·타임아웃·정리 실패는 종료 코드 1입니다. 점검은 업무 생성·큐 등록·결과 검토 기록·서버 활성화를 하지 않습니다.

## 검증 범위와 다음 단계

합성 stdio 프로세스로 비공개 설정·권한/링크/FIFO/UTF-8·오프라인 무호출·고정 실행 계약·단일 turn·인증 실패·시간 초과·중단·임시 파일 제거·출력 비노출·개발 인증 대체 금지를 검사했습니다. 이는 실제 제공자 호출의 증거가 아닙니다.

현재 클라우드 작업에는 OFFICE_AI_CONFIG가 지정되지 않아 실제 호출을 수행하지 않았습니다. 운영자가 비공개 파일·제품 키·정책을 준비한 뒤 위 명령으로 실제 연결을 점검할 수 있습니다. 성공해도 실제 큐 디스패치와 HTTP 접수 활성화는 별도 구현·검증이 필요합니다. 운영 배포·도구/파일 처리·비용 상한·개인정보 처리·실제 실패 복구 검증은 미완료입니다.
