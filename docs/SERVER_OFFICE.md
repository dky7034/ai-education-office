# 서버 집계 현황과 오피스 표시

로그인한 계정의 정량 집계 상태를 오피스 캐릭터·현황 패널에 표시합니다. 실제 계산은 기존 서버 워커가 수행하며, 캐릭터는 저장된 상태를 읽어 표현합니다. AI는 계속 미연결입니다.

## 사용 방법

1. 로그인한 뒤 상단의 **서버 집계 보기**를 선택합니다. 계정 전체의 집계 현황을 표시하며 검색 조건·업무 목록 페이지와 별개입니다.
2. 분석가 캐릭터나 아래 직원 버튼을 선택해 대표 집계의 상태·업무·첨부·선택 버전을 확인합니다. **집계 실행·결과·검토 보기**는 해당 실행의 저장 기록으로 이동합니다.
3. **업무 시연 보기**로 돌아가면 기존 6가지 예시 시연을 사용할 수 있습니다. 서버 보기로 전환할 때 진행 중인 시연은 초기화하지만 저장 업무·집계·검토 기록은 변경하지 않습니다. 서버 보기에서는 시연 시작 버튼을 비활성화합니다.

요청을 보관한 것만으로 집계를 시작하지 않습니다. 로그인/보기 전환/직원 선택/이동 애니메이션/현황 GET은 집계 접수·취소·승인·AI 호출을 만들지 않습니다. 저장된 업무의 첨부·열 설정에서 집계를 명시적으로 접수합니다. 서버 없는 단일 HTML은 계속 시연 전용이며 서버 보기와 API 요청을 제공하지 않습니다.

## 표시 기준

정량 집계는 원래 요청 종류와 관계없이 **데이터 분석가** 역할로 표시합니다. 예를 들어 공지 업무에 첨부한 CSV의 정량 집계는 분석가에 표시하며 문서 전문가가 메일을 작성했다고 표시하지 않습니다. 운영팀장은 사용자 검토 대기 건수만 표시하며 캐릭터가 결정을 확정하지 않습니다. 연결된 실제 실행이 없는 다른 역할은 대기 상태입니다.

대표 실행은 전체 실행 중 → 전체 대기 → 첨부별 최근 실행의 검토 대기 → 첨부별 최근 종료 기록 순으로 정합니다. 대기/실행은 접수 시각이 빠른 순, 나머지는 접수 시각·ID 내림차순입니다. 첨부별 최근 실행보다 오래된 실행이 아직 진행 중이어도 대표 대상으로 포함합니다. 여러 실행을 캐릭터 하나로 표현하므로 전체 대기·실행 건수를 함께 표시합니다.

| 서버 기록 | 분석가 표시 | 위치/의미 |
| --- | --- | --- |
| 집계 없음 | 대기 | 요청 보관만으로 이동하지 않음 |
| queued | 집계 대기 | 대기 위치 |
| running | 집계 실행 중 | 분석 책상으로 이동 |
| completed + pending | 검토 대기 | 검토 공간, 사용자 확인 대기 |
| completed + approved/rejected | 승인 기록/반려 기록 | 집계 완료 위치, 당시 결정 표시 |
| completed + summary_only | 요약만 보관 | 과거 파일 없는 완료 기록 |
| failed/cancelled | 집계 실패/집계 취소 | 오류/취소 구분 |
| 연결 단절·재생 중·GET 실패·잘못된 응답 | 상태 확인 필요 | 진행 중 애니메이션 대신 대기 상태, 마지막 데이터 별도 유지 |

현재 상태는 서버 스냅샷을 적용하며 지난 모든 단계를 시연 타이머로 재현하지 않습니다. 움직임 자체는 시각화이므로 실제 워커의 위치·속도·진행률을 의미하지 않습니다. 검토 기록은 파일 무결성의 현재 유효성을 주장하지 않으며 결과 상세에서 재검사합니다.

## 갱신·계정·접근성

업무 화면의 기존 WebSocket 연결·영구 커서를 함께 사용하고 추가 소켓을 열지 않습니다. 알림/재연결/heartbeat/창 복귀 시 오피스 현황도 GET으로 읽습니다. 자동 조회는 10초 제한이며 이전 요청과 계정의 늦은 응답은 적용하지 않습니다. 실패하면 마지막 확인 시각·기록·오류를 표시하고 분석가는 ‘상태 확인 필요’로 바뀝니다. 다음 확인 주기나 업무 화면의 **자동 갱신 다시 연결**로 다시 확인합니다. 응답의 상태·건수·종류가 잘못되어도 화면에 적용하지 않습니다.

로그아웃·세션 회수·계정 변경 시 상위 오피스 데이터도 지우고 시연 보기로 돌아갑니다. 다른 계정의 이전 응답은 다시 표시하지 않습니다. 직원 버튼으로도 모든 상태/선택을 확인할 수 있고 기존 동작 줄이기·캔버스 실패 안내를 유지합니다. 현황과 최근 서버 기록은 시연 이벤트 로그와 분리합니다.

## API·저장

`GET /api/jobs/office`는 기존 세션·X-Office-Account·계정 소유권·no-store를 적용합니다. 검색/페이지를 포함해 쿼리 매개변수를 받지 않습니다. 계정 전체 조회가 필요한 전용 읽기 모델입니다.

응답은 `{ executionMode: "quantitative_summary", aiConnected: false, totals, focus, recent }`입니다. totals는 jobs/queued/running/latestRuns/completed/failed/cancelled/reviewPending/approved/rejected/summaryOnly이며 focus는 대표 실행 또는 null, recent는 첨부별 최근 실행 중 최신 최대 5개입니다. 실행 항목은 실행/업무/첨부 ID·업무 제목·파일 이름·상태·선택 버전·검토 분류·접수/시작/종료 시각입니다. 요청 내용·검토 의견·인증 정보·결과 JSON·파일 내용은 반환하지 않습니다.

대기/실행 건수는 모든 실행, 완료/실패/취소/검토 건수는 첨부별 최근 실행 기준이므로 서로 배타적인 총합이 아닙니다. 검토 분류는 [업무 현황](JOB_ACTIVITY.md)·[검색](JOB_SEARCH.md)의 SQL 기준을 공유합니다. 한 읽기 트랜잭션으로 건수·대표·최근 기록의 일관성을 유지하며 파일을 읽거나 DB를 쓰지 않습니다. 스키마 v9와 기존 jobs의 received/not_connected 상태를 유지합니다. 신규 마이그레이션은 없습니다.

전체 AI 업무 상태 모델·Codex 실행 연결·실제 실행 진행률·대규모 성능·운영 배포는 후속 작업입니다.
